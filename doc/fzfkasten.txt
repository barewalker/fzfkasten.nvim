*fzfkasten.txt* for Fzfkasten.nvim

Fzfkasten.nvim is a lightweight and fast Zettelkasten plugin for Neovim, using fzf-lua.

HEALTH

`:checkhealth fzfkasten` reports what fzfkasten needs from outside itself --
the notes directory, fzf-lua and the `fzf` binary, ripgrep, the templates you
configured, and where captured tasks will land. Reach for it first when a
picker opens empty or a command quietly does nothing.

ROMAJI

`<alt-/>` in the pickers narrows by romaji: type `kaigi`, match 会議. That
takes a migemo -- a converter that reaches the kanji, which needs a
reading-to-headword dictionary and not just a kana table. Two programs can do
it and either will be used:

  ttyskk    `ttyskk migemo`, reading the SKK dictionaries already on the
            machine. Nothing beyond itself, about 30ms per query.
  kensaku   kensaku.vim, which runs on denops and so brings Deno with it,
            plus a 2.1MB dictionary downloaded on first use.

`romaji.backend` decides. The default "auto" tries ttyskk first and falls back
to kensaku, so a machine with either just works. Name one ("ttyskk" /
"kensaku") to pin it -- asked for ttyskk on a machine without it, <alt-/>
stays hidden rather than quietly starting Deno instead. `false` turns the key
off. A table of your own with available() / regex() / rg_regex() supplies a
backend; both flavours are needed, since the pickers filter in Lua with a `\m`
Vim regex while content search shells out to `rg`, and handing `rg` a Vim
pattern does not fail -- it matches nothing.

`ttyskk` takes cmd, limit and timeout under `romaji.ttyskk`.
`:checkhealth fzfkasten` reports which backend answered.

COMMANDS

- FzfKastenDaily: Open today's daily note.
- FzfKastenWeekly: Open this week's weekly note.
- FzfKastenLog: Browse recent daily/weekly notes by date in one picker --
  existing notes preview and open, a date with no note is created from its
  template. <ctrl-x> enters a date manually. (FzfKastenPickDailyDate is an alias.)
- FzfKastenFindNotes: Search for notes. <alt-/> narrows by romaji, matching a
  note's path and its own headings -- a collection written in Japanese is
  often filed under ASCII names, and paths alone then match almost nothing.
  Set romaji.headings = false for paths only. Blank input clears the filter.
  See ROMAJI below.
- FzfKastenTags: Search for tags.
- FzfKastenInsert: Insert a link to a note. <alt-/> narrows by romaji too,
  the same way FzfKastenFindNotes does.
- FzfKastenSearchContent: Live-grep note bodies. <alt-/> runs a romaji search
  instead (the backend builds an rg pattern), which suits Japanese bodies.
- FzfKastenTasks: Pick an open `- [ ]` task and jump to it. <ctrl-x> marks it
  done. <alt-a> captures a new task via a guided input (text, tags picked from
  those already in your notes, then a due date). <alt-/> narrows the list by
  romaji (e.g. `kaigi` finds 会議); shown only when a backend is installed,
  blank input clears it.
  <alt-s> cycles the ordering (priority -> due -> added -> priority) and
  <alt-r> reverses it; the active ordering shows in the prompt. A task with no
  due date sorts last under `due`, not first.
  A checkbox indented under a task is a subtask of it and inherits
  tasks.require_tag, so the steps of one job need tagging once, not each. The
  list keeps a subtask under its parent and shows the parent's progress
  ([1/2]); a task whose parent is a plain bullet, or whose parent the view
  filtered out, carries that line along instead (`task  <- context`).
- FzfKastenTaskList: The same tasks as an ordinary buffer, worked with Vim
  keys -- j/k/gg/G// are Vim's, and the actions are unmodified letters:
  <enter> open, x done, c cancel, t tag, a add, u undo, s/S sort/reverse,
  i inbox, r rescan, q close. Nothing is mapped that Vim needs. The buffer is
  never written; actions rewrite the notes and it redraws from disk.
  A split below previews the task's note around its line, following the
  cursor. All three of Vim's scroll pairs act on it from the list --
  <c-d>/<c-u> half a screen, <c-f>/<c-b> a page, <c-e>/<c-y> a line -- so the
  rule is "scrolling is the preview, the list moves by cursor"; with no
  preview up they fall through to Vim. p goes into it (an ordinary window, so
  every Vim key works; <esc> or <c-q> comes back), P hides it. Every key, the
  preview's included, is tasks.list.keys.<name>: a key, a list of keys all
  bound to that action, or false to leave that key to Vim. Each carries a
  description in words, so which-key reads as an answer rather than a field
  name.
  A listed buffer, so a bufferline shows it as a tab and you switch back to
  it like any open file; switching back re-scans and restores the preview.
  Configure with tasks.list (open = full/split/vsplit/tab, listed, source,
  preview = { enabled, height }, keys).
- FzfKastenTaskListInbox: The same buffer, showing the inbox.
- FzfKastenTaskToggle: Toggle the checkbox on the current line.
- FzfKastenFollowLink / FzfKastenGotoLink: Follow the [[wikilink]] under the
  cursor. An anchor puts the cursor on that heading ([[note#Results]] opens
  note at its "## Results"), matched on the heading text, case-insensitively;
  a heading that is not there opens the note anyway and warns.
- FzfKastenShowBacklinks: List every line in the collection that links to the
  current note. [[note]], [[note|alias]] and [[note#heading]] all count; only
  whole names match, so [[note-old]] is not a link to [[note]]. The note's own
  links to itself are left out, whether or not the path you reached it by went
  through a symlink.
- FzfKastenRenameNote: Rename the current note and retarget every link to it:
  [[old]], [[old|alias]], [[old#heading]] and [[old#heading|alias]] all follow,
  anchor and alias untouched. Only whole names match, so [[old-notes]] is not a
  link to [[old]]. The file moves before any link is rewritten, so a failed
  move changes nothing; a note you have open with unsaved changes is edited in
  its buffer rather than underneath it. Reports how many notes it touched.
- FzfKastenTaskAdd: Capture a new task to one fixed note (tasks.capture_note,
  or the first tasks.always entry). Takes text, or prompts with no argument.
- FzfKastenTaskInbox: Triage checkboxes not tagged as tasks. <ctrl-t> tags one.
- FzfKastenTaskTag: Tag the current line as a task, making it a checkbox first
  if it isn't one. Takes a range, so a selection is tagged in one go.
- FzfKastenTaskCancel: Drop the task on the current line -- out of the lists,
  still in the note -- or reopen it if already dropped. <ctrl-d> in the picker.
- FzfKastenTaskDue: Set the due date on the current task, e.g.
  `:FzfKastenTaskDue 2026-07-25` (or `2026-07-25T15:00` for a time). Also takes
  a relative spec -- tomorrow / 明日 / +3d / 2w / fri / 金 -- resolved to an
  absolute day; with no argument, clears the due date.
- FzfKastenTaskUndo: Put back the last task line the picker rewrote. <alt-u>
  in the picker. Not Vim's undo: edits you make in a buffer are `u`'s.
